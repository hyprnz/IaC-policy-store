# IaC pipeline control

This policy enforces actions to specific AWS resources that are considered not safe for a pipeline to change - the obvious example being the drop & recreate or a destroy of a datastore.

It's envisaged this policy will evolve over time based on what we consider a deployment pipeline should do.

This policy has been designed to be tested with [Conftest][1]

## Executing the policy

The policy requires a Terraform plan file in a json format, which can be generated by the following Terraform/Terragrunt commands

```
terraform|terragrunt plan -out tf.plan

terraform|terragrunt show -json  tf.plan > tf-plan.json
```

To pull the policy rego file into the service ci, it's recommended to pin a reference (i.e. x.y.z) to the repo policy file.

```
conftest pull git::https://github.com/hyprnz/IaC-policy-store.git//terraform-pipeline/policy?ref=x.y.z
```

Using [Conftest][1] one can test the plan is compliant with the policy

```
conftest test tfplan.json --namespace terraform.pipeline_control
```

## Test outcomes

[Conftest][1] will show the status of the test and will provide a reason for any test failures - any policy test failures should break the build. Conftest supports various test output artifacts which can be referenced in the [--output options](https://www.conftest.dev/options/).


## Policy Tests

A test file has been provided and tests can be run during development to confirm behaviour.

```
conftest verify --policy . --show-builtin-errors
```

Once the policy has been updated and tested, a new release should be created then the reference should be updated in the relevant services.
